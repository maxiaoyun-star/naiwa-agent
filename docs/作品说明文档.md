# 奶娃 Agent · 作品说明文档

> 参赛赛道：AI 智能体创意设计赛 · 主题「AI + 校园服务」
> 作品形态：Android App（端侧大模型 + 校园系统直连）
> 团队：长春理工大学

---

## 一、需求背景

校园里最高频的三类查询，恰恰是最麻烦的三类：

1. **查课表**：要开浏览器、登录统一身份认证、点进门户、再点教务，网络慢的时候一轮下来两分钟。
2. **查考试**：考场和座位号散落在不同页面，考前一周几乎每天都要看一遍。
3. **问流程**：补办学生证去哪、教室借用找谁、绩点怎么算——信息在通知、群聊、学长学姐脑子里，搜不到准确答案。

更关键的是**隐私顾虑**：课表、成绩、心理状态这类信息，学生并不愿意随手发给一个云端大模型。这也是很多人"知道有 AI 但不用"的真实原因。

所以本作品的目标不是再做一个聊天框，而是：**把推理搬进手机，把校园数据留在手机，把交互压缩到一句话。**

## 二、功能介绍

### 2.1 一句话对话（核心）

- 「今天有什么课」→ 直接列出当天课程、节次、教室、教师
- 「周三的课」→ 按星期过滤
- 「第 5 周课表」→ 按教学周过滤
- 「考试安排」→ 考试科目、时间、考场、座位号
- 「我的信息」→ 当前登录账号、学院、专业
- 其他问题（学习规划、办事流程、闲聊）→ 本地模型自由回答

### 2.2 端侧推理，断网可用

- 内置 `Qwen3.5-2B-Q4_K_M`（1.19 GB），llama.cpp 在手机 CPU 上推理
- 断网、飞行模式下对话功能照常工作
- 对话内容不上传任何服务器

### 2.3 校园系统直连

- 接入学校统一身份认证（CAS），扫码式的一次性登录
- 登录后只保存**会话 Cookie**（加密存储），默认**不保存密码**
- 会话过期后自动提示重新登录

### 2.5 系统兼容

- 支持 **Android 13（API 33）至 Android 17（API 37）**，arm64 架构
- 已处理 Android 15+ 强制 edge-to-edge（读取系统栏真实高度让出安全区）
- 已按 16 KB 内存页对齐编译原生库（Android 16 起新硬件的硬性要求）
- 权限只要两项：网络与网络状态；不申请任何存储权限

### 2.6 双层模型路由

| 模式 | 行为 | 适用场景 |
|---|---|---|
| 自动（默认） | 本地优先，失败切云端 | 日常 |
| 仅本地 | 只走端侧，绝不联网 | 隐私敏感 / 无网 |
| 仅云端 | 只走 API | 手机带不动模型时 |

云端仅支持国内合规平台（智谱 / 通义 / 豆包 / DeepSeek / 自定义 OpenAI 兼容接口）。

## 三、实现思路

### 3.1 整体架构

```
┌──────────────── 手机（Android） ────────────────┐
│  Kivy 纯白 UI                                    │
│    ├── 对话页（流式渲染）                        │
│    ├── 校园查询页（课表 / 考试）                 │
│    ├── 登录页（CAS 表单 + 图形验证码）           │
│    └── 设置页（模型 / API / 教务接口）           │
│                                                  │
│  Agent 运行时                                     │
│    意图识别（规则）→ 工具调用 → 数据注入 → 生成   │
│                                                  │
│  LLM 路由 ──┬── 本地 llama.cpp（GGUF，2B Q4）    │
│             └── 云端 OpenAI 兼容 API             │
│                                                  │
│  校园服务：CAS 客户端 + 门户适配器（urllib）      │
└──────────────────────────────────────────────────┘
```

### 3.2 三个关键设计决策

**① 不用模型做 function calling，改用规则意图 + 确定性工具**

1–2B 参数的小模型在中文工具选择上准确率不稳定，还会编参数（比如把"周三"编成"周四"）。
所以意图识别写成关键词 + 槽位抽取（星期、周次），准确率 100% 且零延迟；
模型只负责"把查到的数据说人话"。这样即使模型输出跑偏，**课表数据也不会错**。

**② 数据只来自工具，模型无权编造**

提示词里明确约束"只能依据【校园数据】回答"，并且在模型不可用时直接把数据原文交给用户。
校园场景里，编错一节课比不回答严重得多，这条是硬约束。

**③ 原生库用 C 薄封装隔离版本风险**

llama.cpp 的 `llama_context_params` 等结构体在不同版本间会变，Python 侧 ctypes 按值传结构体
一旦版本不匹配就是内存踩踏。因此把不稳定部分编译进 `libnaiwa_llama.so`，
只对 Python 暴露 4 个稳定函数（init / load / generate / free），
且每次生成新建 context、用完释放，绕开 KV cache 接口的改名问题。

### 3.3 纯白界面

不引入 KivyMD 等组件库，全部用 Kivy 原生 canvas 手绘圆角卡片、气泡、胶囊按钮。
好处：APK 体积小、启动快、样式完全可控。设计语言是「白底 + 1px 浅灰描边 + 近黑强调色」，
只有一句话（输入框占位符）和一个状态胶囊，信息密度低到不打扰。

### 3.4 可靠性

- 模型加载失败 → 自动降级 API → 再降级为模板回答，App 永远能给出有用结果
- 下载模型写 `.part` 临时文件 + 大小校验，断网续传，不会留下坏文件
- 所有推理/网络在后台线程，UI 只用 `Clock.schedule_once` 回主线程刷新

## 四、技术贡献（可验证）

1. **端侧推理的可移植封装**：`native/naiwa_llama.c` 定义了一层稳定 C ABI，把 llama.cpp 的版本
   演进隔离在 C 里；Python 侧只依赖 4 个函数，CI 可独立编译该 `.so`，编译失败不影响 APK 打包。
2. **面向小模型的"确定性智能体"范式**：意图规则化 + 工具确定化 + 模型仅负责表述，
   在 2B 模型上取得了比 function calling 更稳定的任务完成率。
3. **CAS + 门户的零依赖实现**：只用标准库 `urllib` / `html.parser` 完成登录页解析、
   验证码会话、票据跳转、Cookie 域管理，Android 端无需 `requests` / `cryptography` 等原生依赖。
4. **宽容的教务数据适配**：字段别名表覆盖拼音 / 中文 / 英文三套命名，返回体形状支持
   数组、`data.rows`、`rows`、`kbList` 等，换一所学校只需改接口地址而不改解析代码。

## 五、AI 辅助说明

按赛事要求，如实标注：

| 模块 | AI 参与方式 | 人工部分 |
|---|---|---|
| 需求拆解与评分维度分析 | 用国内大模型辅助梳理评审维度、规划功能优先级 | 场景选择、取舍决策由团队完成 |
| 代码骨架 | 用 AI 辅助生成初版代码结构与注释 | 接口抓包、真机调试、逻辑修正由团队完成 |
| 提示词（系统人设） | AI 辅助起草，多轮迭代 | 结合校园语境改写、约束"不许编数据" |
| 界面文案 | AI 辅助润色 | 最终措辞由团队确定 |
| 文档 | AI 辅助整理结构与措辞 | 技术细节均来自实际实现与验证 |

**未使用**任何境外模型或境外开发平台；未直接套用任何平台的现成智能体模板。

## 六、已知限制与后续计划

| 限制 | 原因 | 计划 |
|---|---|---|
| 教务接口地址需手动配置 | 学校门户接口无公开文档，需本人账号抓包 | 提供抓包指引与探测脚本；后续做一次配置后云端共享 |
| 端侧 2B 模型知识面有限 | 参数量约束 | 后续接入校园知识库 RAG（本地向量检索） |
| 未接入 Keystore | 纯 Python + 标准库实现 | 后续用 jnius 调 Android Keystore 包装密钥 |
| 成绩查询未接入 | 接口需单独抓包 | 下一版补 |
